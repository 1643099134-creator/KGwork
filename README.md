# 便利本

团队便签、协作写作和工作安排。Cloudflare D1 保存团队内容，Supabase Auth 验证邮箱验证码。正式用户不依赖 ChatGPT 账号。

## 邮箱登录配置

1. 在 Supabase 项目中启用 Email 登录，将 Magic Link 与 Confirm Signup 邮件模板改成包含 `{{ .Token }}` 的验证码邮件；建议验证码10分钟有效。
2. 配置能向实际成员邮箱投递邮件的 SMTP 服务。默认测试邮件发送限制不适合正式团队使用。
3. 在 Sites 运行环境中设置 `.env.example` 列出的键。使用 publishable/anon key，不能使用 service-role key。`ALLOWED_EMAILS` 是逗号分隔的授权邮箱，`TEAM_ADMIN_EMAIL` 是唯一可创建团队的管理员邮箱。
4. 将网站入口开放为可访问登录页，团队数据由应用内邮箱白名单与团队成员权限保护。开放入口必须在配置检查及真实邮箱验证码验证完成后进行。当前网站保持所有者私有。
5. 发送、验证均通过 Supabase Auth。访问令牌只存 HttpOnly、SameSite=Lax Cookie；每次读取团队内容均向身份服务校验令牌及邮箱白名单。登录最长1小时，过期后重新获取验证码。

## 使用

- 管理员邮箱登录后创建团队，再生成一次性邀请码（24小时有效）给成员。成员必须同时在邮箱白名单内。
- 便签按分类整理，可切换为文稿或任务，指定负责人、截止日期、进度，可置顶或归档。
- 编辑后点击「保存到团队」。团队内容每10秒刷新。采用版本冲突检测，冲突时保留草稿供人工合并；不支持逐字实时协同或光标显示。
- 评论和每次保存的版本均存数据库；历史内容可以恢复到编辑区，保存后生成新版本。
- 权限有管理员、可编辑、只读；只读不能修改或评论。
- 导出按钮下载便签和分类 JSON（不含评论和历史）。

## 开发和部署

Node.js >=22.13。`npm run dev` 在5173启动。`npm run db:generate` 生成迁移，`npm run build` 构建 Worker。生产迁移在 `drizzle/`，平台发布时应用。

本地预览继承 starter 的 loopback 模拟账号，仅用于本地测试，不进入生产身份校验。`/login` 可直接查看邮箱登录页面。测试数据库与生产隔离。

当前已完成内容和权限流程。真正的验证码投递需连接 Supabase、配置生产环境和邮件服务后执行端到端验证。

## 个人任务工作台（/tasks）

- 管理员默认进入伙伴清单总览，每人一张汇总卡，显示待办、进行中、完成数量；点击后显示该成员完整列表。
- 管理员派发任务，设定负责人、截止日期、优先级；任务按优先级和日期排序。
- 成员只能更新自己的任务进度和工作反馈。个人任务默认仅本人及管理员可见。
- 管理员可额外指定某些成员只读查看某人的清单。授权不能转授，不能修改被授权任务或发表评论。撤销后服务端立即拒绝读取。
- 消息只通过网站右上角铃铛提供，不发送任务邮件。未读状态存数据库，活跃页面每10秒刷新，收到新任务时显示提示。
- 仅管理员可以生成微信只读分享链接。链接包含当前筛选出的任务ID，显示这些任务最新的标题、优先级、进度和日期；不包含工作说明、评论或成员邮箱。后续新增任务不会自动加入。
- 分享链接1/7/30天到期，可以随时撤销。任务归档、改派或成员移出后，不再在原链接中显示。
- 登录验证码邮件仍由 Supabase Auth SMTP 负责；任务通知不依赖任何额外 SMTP 密钥。
